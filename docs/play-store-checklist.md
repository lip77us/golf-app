# Google Play — what it takes to get Halved approved

Written 2026-08-21, when the Android side was still the untouched Flutter
template: it built with a debug key, called itself `golf_mobile`, and wore the
stock Flutter logo. This is the counterpart of `go-live-checklist.md`, which
covers the App Store.

The order below is deliberate. The account clock (§1) is the only item with a
mandatory two-week wait in it, so it starts first and everything else happens
while it runs.

---

## 1. The developer account, and the 14-day clock

**Do this first.** A **personal** developer account registered after
2023-11-13 cannot publish to production until it has run a **closed test with
at least 12 testers opted in continuously for 14 days**. The clock starts when
the *twelfth* tester opts in — not when the track is created, and it resets if
you drop below twelve. Organization accounts are exempt, but need a registered
legal entity and a D-U-N-S number, which takes longer to obtain than the 14
days it would save. Personal is the faster route for Halved.

- [ ] Register at play.google.com/console — $25, one time, plus identity and
      address verification (a few days; can be slower).
- [ ] Line up **12 real people with Google accounts and Android phones**. They
      must accept the opt-in link and actually install. Golf group first.
- [ ] Create the closed-testing track, upload the first bundle, send the
      opt-in link, and **start the 14 days as early as possible**.

Everything below can proceed in parallel with that fortnight.

## 2. Repo work — done 2026-08-21

Recorded here because these are the decisions, not just the diffs.

- **Application ID: `golf.halved.app`.** Replaced the template's
  `com.lipkin.us.golf_mobile`. This is permanent — Play binds the listing to
  it at first upload and it can never be changed afterwards, so it was worth
  fixing before the first upload rather than living with a scaffold name
  forever. The Kotlin package and `namespace` moved with it. (iOS keeps its own
  `us.lipkin.golfapp`; the two never have to match.)
- **`android:label` is now `Halved`** — it was `golf_mobile`, which is what
  would have appeared under the home-screen icon.
- **Launcher icon.** Was the stock Flutter logo, byte-identical to the
  template's. Now generated by `flutter_launcher_icons` as a proper adaptive
  icon: `#0B1F1A` background layer plus a transparent foreground, with a
  monochrome layer so Android 13+ themed icons work. The foreground art is
  generated from `assets/icon/halved_icon.png` — see §7 for why the scale is
  what it is.
- **Notification icon.** Android draws only the *alpha* of the status-bar icon
  and tints it, so a full-colour launcher icon renders as a white square.
  `res/drawable-*/ic_notification.png` is a flat white silhouette of the mark,
  wired up with `default_notification_icon` / `_color` / `_channel_id`
  meta-data in the manifest.
- **`INTERNET` is declared explicitly** in the main manifest. It was only ever
  arriving via the Firebase libraries' merged manifests (debug and profile have
  their own), which meant dropping Firebase would have silently shipped a
  release build with no network.
- **Android App Links** intent-filter added for
  `https://link.halved.golf/watch/*`, with the matching `assetlinks.json` route
  on the backend — see §6.
- **Release signing** reads `android/key.properties` (gitignored) — see §3.

Verified after the changes: the release bundle builds, the merged manifest
carries `package="golf.halved.app"`, `android:label="Halved"`,
`targetSdkVersion="36"`, `minSdkVersion="24"`, and a permission set of
`INTERNET`, `ACCESS_NETWORK_STATE`, `POST_NOTIFICATIONS`, `WAKE_LOCK`,
`c2dm.permission.RECEIVE` — and the debug build installs and launches on a
Pixel 8 / API 35 emulator under the new package.

That permission list matters for more than tidiness: **no SMS permission
appears anywhere**. The invite flow hands off through an `ACTION_SENDTO`
intent (`packages/halved_sms`) rather than holding `SEND_SMS` itself, so Play's
Permissions Declaration Form — the usual rejection trap for an app that texts
invitations — never comes into play. Keep it that way.

## 3. The upload keystore

Play rejects debug-signed bundles. Create the keystore once:

```sh
keytool -genkey -v -keystore ~/.android-keystores/halved-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias halved-upload
```

Then write `mobile/android/key.properties` (gitignored):

```properties
storeFile=/Users/<you>/.android-keystores/halved-upload.jks
storePassword=<store password>
keyAlias=halved-upload
keyPassword=<key password>
```

Without that file the build still works — it falls back to the debug key and
logs a warning — so a missing keystore shows up as a Play rejection rather
than a build failure. Check the warning is absent before uploading.

**Back the `.jks` and its passwords up somewhere durable and off this machine.**
Under Play App Signing the `.jks` is the *upload* key, so losing it is
recoverable (Google can reset it) but slow; losing it while also not enrolled
in Play App Signing would end the ability to update the listing at all.

Build the artefact Play wants:

```sh
flutter build appbundle --release
```

## 4. Firebase — must be redone

The `google-services.json` in the repo was downloaded for a **mistyped** package
(`com.lipkin.usgolf_mobile`, missing a dot), which failed every Android build
with *"No matching client found for package name"*. The file's `package_name`
has been corrected locally so the build works, but the `mobilesdk_app_id` in it
still belongs to that mistyped registration, and FCM registers tokens against
the app id.

- [ ] Firebase console → project `halved-f5327` → add an Android app with
      package name **`golf.halved.app`**.
- [ ] Download the fresh `google-services.json` and replace
      `mobile/android/app/google-services.json` wholesale.
- [ ] Delete the mistyped app registration.
- [ ] Verify end to end: sign in on a device, confirm the device token reaches
      the backend (`registerDevice`, platform `android`), and send a real push.
      Untested until then — the emulator run only proves the app launches.

## 5. Play Console — store listing and declarations

Reuse the App Store copy in `app-store-listing.md`, including its discipline of
keeping betting vocabulary out. Play's content rating and its Real-Money
Gambling policy are separate things: Halved never moves money — it keeps score
and tells people what to settle between themselves — so it is not a gambling
app, but listing copy that reads like a betting product invites the reviewer to
treat it as one.

- [ ] **Graphics** — `docs/store/play/icon-512.png` and
      `feature-graphic-1024x500.png` are generated and in the repo. The feature
      graphic is Play-only; Apple has no equivalent.
- [ ] **Screenshots** — 2–8 phone shots, captured from an Android device or
      emulator against seeded demo data (`adb exec-out screencap -p > shot.png`).
      Do not reuse the iOS ones; they show iOS chrome.
- [ ] **Short description** (80 chars) and full description (4000).
- [ ] **Privacy policy URL**: `https://halved.golf/privacy`.
- [ ] **Data safety form** — mirrors `app-privacy-labels.md`: name, email, phone
      number, user content, user ID, plus the FCM token as a device identifier.
      Encrypted in transit; user can request deletion; no sharing with third
      parties; no tracking; no advertising.
- [ ] **Content rating** — the IARC questionnaire. Answer the gambling
      questions honestly: no real-money wagering, no simulated gambling
      mechanics, no purchase of chips or credits.
- [ ] **Target audience** — adults. Not "Designed for Families".
- [ ] **Data deletion** — declare the in-app path (Settings → Delete Account)
      and give `https://halved.golf/support` as the web URL, which already
      documents it.
- [ ] **App access** — the app is login-gated, so reviewers need the demo
      phone + OTP bypass. Same procedure and copy as
      `app-store-review-notes.md`; make sure `seed_demo` has been run against
      prod and `REVIEW_BYPASS_PHONE`/`REVIEW_BYPASS_CODE` are set on Railway.
- [ ] **Ads**: none. **Financial features**: none — do not declare any.

## 6. Android App Links (after the first upload)

The intent-filter is in the manifest with `autoVerify="true"`, and the backend
serves `/.well-known/assetlinks.json`. It lists no certificates until you set
them, so verification simply fails and watch links open the web page — the
correct pre-launch behaviour, not a bug.

- [ ] After the first bundle is uploaded: Play Console → Test and release →
      Setup → App signing. Copy **both** SHA-256 fingerprints — the app-signing
      certificate Google generates *and* your upload certificate.
- [ ] Set `ANDROID_CERT_FINGERPRINTS` on Railway to both, comma-separated.
- [ ] Confirm `https://link.halved.golf/.well-known/assetlinks.json` returns
      them over HTTPS with no redirect, then reinstall and tap a watch link.

## 7. Regenerating the icons

`dart run flutter_launcher_icons` in `mobile/` rebuilds every platform's icons
from `pubspec.yaml`. The Android adaptive layers are pre-generated art, not the
raw brand icon, for a reason worth not rediscovering:

An adaptive icon is a 108dp layer of which the launcher shows the middle 72dp
and may mask it to a **circle** of 66dp. `flutter_launcher_icons` additionally
insets each layer by 16%. The mark's pennant reaches into a corner, so it clips
against a circular mask well before a square one — at a source fill of 0.78 the
flag tip was cut off. 0.70 lands the mark at roughly 48% of the finished layer,
comfortably inside the circle. The generation script lives in this checklist's
history; regenerate by re-running it against `assets/icon/halved_icon.png` if
the brand art ever changes, and **check the result against a circular mask**
before shipping it.

## 8. Device QA before the first upload

Emulator smoke-testing is not enough for the platform-specific parts:

- [ ] **Hardware back button** through the whole navigation stack — the single
      most common Android bug in an iOS-first Flutter app. Back must unwind
      screens, not drop straight out of the app, and must not strand a
      half-finished round.
- [ ] Phone login over real SMS.
- [ ] The Android 13+ runtime notification permission prompt, then a real push.
- [ ] The SMS invite hand-off: it leaves Halved for the messaging app (Android
      has no in-app compose sheet), and the back button must return cleanly.
- [ ] Share sheet, offline queue and reconnect, and a full round end to end.
